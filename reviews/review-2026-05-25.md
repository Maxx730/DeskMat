# Code Review — DeskMat
**Date:** 2026-05-25  
**Scope:** Full codebase (Swift + Metal)  
**Files reviewed:** 34 Swift files, 2 Metal files

---

## Overall Assessment

The codebase is well-structured and production-quality for an indie macOS app. The AppDelegate-extension pattern keeps concerns cleanly separated, the Metal pipeline is correctly layered, and there is meaningful test coverage. The main issues are a handful of silent-failure paths, a hardware ID persistence bug in the license system, and some architectural leakage (enums and services living in the wrong files).

---

## Strengths

- **AppDelegate split by concern** — `AppDelegate+Panel`, `AppDelegate+AutoHide`, `AppDelegate+FullscreenDetection`, `AppDelegate+Windows`, and `AppDelegate+Appearance` each have a single responsibility. Easy to navigate and extend.
- **Centralized strings** — `Strings.swift` keeps all user-facing text in one place. No scattered string literals.
- **Metal multi-pass rendering** — The offscreen texture → edge highlight → corner mask pipeline is solid and correctly handles the `.none` style fast path.
- **Shader prefix convention** — Every shader's helper functions use a per-shader prefix (`sf_`, `tg_`, `cel_`, etc.) to prevent Metal linker collisions. Good practice.
- **License system design** — Optimistic grant on launch, revoke only on an explicit `valid: false` from a 200 response. Network failures do not revoke the license. Keychain storage with versioned `StoredLicense` struct.
- **Archive import path traversal prevention** — `importDock` sanitises filenames with `URL.lastPathComponent` and rejects dot-prefixed names before writing. Correct.
- **System stats arithmetic** — Wrapping subtraction (`&-`) on CPU tick deltas correctly handles counter rollover.
- **`@Observable` usage** — `LicenseManager`, `SystemMonitorService`, and `WindowStateService` use the new `@Observable` macro rather than the older `ObservableObject` pattern. Correct for Swift 5.9+.
- **`task(id:)` for icon loading** — Cancels the previous async task automatically when `iconFileName` changes, preventing stale icon assignment.

## Issues

### High

**1. Hardware ID not persisted between activation attempts (`LicenseManager.swift:181`)**

```swift
private func generateOrRetrieveHardwareId() -> String {
    if let (_, existingId) = readFromKeychain() { return existingId }
    return UUID().uuidString  // new UUID every call if no Keychain entry exists
}
```

If a user's Keychain entry is absent (first activation, or after a Keychain reset), a fresh UUID is generated for each activation attempt. If the server stores hardware IDs for seat tracking, repeated failed attempts register new phantom seats. The UUID should be persisted separately from the license key — e.g. in a dedicated Keychain entry under a different account name — so it survives activation failures.

---

**2. `AppShortcutStore.load()` silently swallows decode errors**

```swift
} catch {
    return []  // no log, no indication anything went wrong
}
```

A corrupted or schema-migrated `shortcuts.json` returns an empty dock with no diagnostic. The user loses their shortcuts silently. At minimum, log the error. Ideally, preserve the raw file under a `.bak` extension before returning `[]` so data can be recovered.

---

### Medium

**3. `HoverSize` and `HoverAnimation` enums defined in `AppShortcutButton.swift`**

These enums are app-level settings types, not implementation details of `AppShortcutButton`. They belong in `AppEnums.swift` alongside `DockPosition`, `ReactiveStyle`, etc. Their current location makes them invisible to anyone searching the enums file.

---

**4. `SystemMonitorService` timer runs even when the widget is hidden**

The 1 Hz polling timer starts on `start()` and runs indefinitely. If the user disables the system widget in settings, the timer is never stopped — the Darwin-level `host_statistics` and `getifaddrs` calls fire every second for the lifetime of the app. `stop()` should be called when the widget is hidden, and the service should only start when the widget becomes visible.

---

**5. `applyFrameRateLimit()` guard on an implicitly unwrapped optional is misleading**

```swift
private func applyFrameRateLimit() {
    guard metalView != nil else { return }
    ...
}
```

`metalView` is declared as `MTKView!` — an IUO. The `!= nil` check works but is semantically confusing because IUOs crash (not return nil) when force-unwrapped while nil. The guard exists to protect against being called before `setup()` completes. The cleaner form is `guard let metalView` which creates a local non-optional binding and makes the intent clear.

---

**6. `makeUniforms(time:opacity:)` reads `bounds` off the main thread**

```swift
func makeUniforms(time: Float, opacity: Float) -> ReactiveUniforms {
    ...
    resolution: SIMD2<Float>(Float(bounds.width), Float(bounds.height)),
```

`draw(in:)` is called by `MTKViewDelegate` on an arbitrary render thread. `bounds` is an AppKit property that is not thread-safe. In practice it is unlikely to crash (bounds is rarely updated during rendering), but it is technically a data race. The resolution should be captured into a stored property on the main thread and read from that in `makeUniforms`.

---

**7. No URLRequest timeout in `WeatherService`**

The Open-Meteo fetch uses the default `URLSession.shared` with no custom timeout. The default is 60 seconds. On a slow network the weather widget blocks its refresh task for a full minute before surfacing an error. A 15–20 second timeout is more appropriate for a widget refresh.

---

**8. `AppShortcutStore.importDock` has no size or count limit on icons**

A malicious `.dskm` archive could contain hundreds of multi-megabyte base64-encoded images. The import loop writes every entry without checking the count or the decoded size. Adding a cap (e.g. 50 icons, 512 KB per icon) would prevent a denial-of-service via a crafted archive.

---

### Low

**9. Double `DispatchQueue.main.async` for panel resize is fragile (`AppDelegate+Appearance.swift`)**

```swift
DispatchQueue.main.async {
    self?.applyAppearance()
    self?.observeProStatus()
    DispatchQueue.main.async {   // second hop waits for SwiftUI render cycle
        ...
        self.repositionPanel()
    }
}
```

The comment documents the intent, but depending on an undocumented relationship between two main-queue hops and SwiftUI's render cycle is brittle. A safer approach is to observe the hosting view's `frameDidChangeNotification` (which already exists in `AppDelegate+Panel.swift`) and do the resize/reposition there instead.

---

**10. `ContentView` accumulates many `@AppStorage` properties**

`ContentView` directly owns 13+ `@AppStorage` properties. As the feature set grows this becomes unwieldy and makes it harder to test layout logic in isolation. Grouping related settings into small `@Observable` view-model objects (e.g. `DockAppearanceSettings`, `WidgetSettings`) would reduce the property count at the view level.

---

**11. `ReactiveBackgroundView.fragmentShaderName` returns `""` for `.none`**

The `rebuildPipeline()` path calls `makePipeline(vertex:fragment:)` with an empty fragment name when `reactiveStyle == .none`, which calls `library.makeFunction(name: "")`. This returns `nil`, so `pipelineState` is set to `nil`. That's fine — `draw(in:)` guards on `pipelineState` — but it triggers a pipeline rebuild every time the style is set to `.none`. A cheaper guard at the top of `rebuildPipeline()` would avoid that work:

```swift
func rebuildPipeline() {
    guard reactiveStyle != .none else { pipelineState = nil; return }
    ...
}
```

---

**12. `AppDelegate+FullscreenDetection` uses undocumented CGS symbols**

Already acknowledged in the file's comment. Worth tracking: Apple has occasionally broken CGS symbol availability across major macOS releases. If a future OS update changes the symbol name or removes it, the app will crash at launch. A `dlsym`-based lookup with a graceful fallback would make this more resilient, though it adds complexity.

---

**13. Unused `gradient` variable in `snowFragment`**

```metal
float gradient = (1.0 - fragCoord.y / u.resolution.x) * 0.4;
```

This value is computed every frame but never used in the return value. The Metal compiler will likely optimise it away, but it is dead code and should be removed.

## Metal / Shader Notes

- **`snowFragment` inner loop starts at `i = 1`** — Correct and documented. The comment explaining the `i = 0` div-by-zero is good; keep it.
- **`tg_topologize` now takes a `lineCount` parameter** — The `/ (lineCount - 1.0)` denominator will produce `inf` if `lineCount == 1.0`. The `mix(12.0, 28.0, ...)` range makes this impossible in practice, but a `max(lineCount, 2.0)` guard would make the invariant explicit.
- **`cellularFragment` inner loop runs 40 iterations unconditionally** — On lower-end integrated GPUs this may be a bottleneck. If performance is a concern, the count could be reduced for the non-hover state since cells are smaller and less visible then.
- **`starfieldFragment` 3×3 neighbourhood loop** — 8 layers × 9 samples = 72 `sf_hash22` + `sf_getStarField` evaluations per fragment. This is the most GPU-intensive shader. The 15fps idle cap helps significantly.

## Test Coverage Notes

- `ReactiveBackgroundViewTests` covers shader routing, uniform construction, and opacity fade math. Good.
- `SettingsTests` covers `AppStorage` round-trips and key distinctness. Good.
- `AppShortcutDataStoreTests` covers export/import including the path traversal case. Good.
- `SystemMonitorServiceTests` covers live system metrics. Good.
- **Gap:** No tests for `LicenseManager` activation/deactivation flows. The hardware ID persistence issue (#1 above) would be caught by a test that calls `activate()` twice without a Keychain entry and verifies the same hardware ID is sent both times.
- **Gap:** No tests for `WeatherService` or `LocationService` (network-dependent, acceptable to leave as integration tests, but a mock URLSession would allow unit testing the parsing logic).
